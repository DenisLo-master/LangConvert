## Проблема, пользователь и цель

Пользователь пишет в нескольких приложениях macOS на разных раскладках.
После смены приложения фактический источник ввода может отличаться от
ожидаемого. Команда переключения должна исходить из текущего системного
состояния. Пользователь не должен вручную исправлять рассогласование.

Второй сценарий: пользователь хотел написать по-русски, но набрал `ghbdtn`
в английской раскладке. Он выделяет текст, конвертирует его в `привет`
и сразу продолжает ввод по-русски, без второго нажатия для смены раскладки.
Требование пользователя: «То есть по последнему символу. Определяем и
применяем новую раскладку».

Уточнение, принятое в Brief: конечные пробелы, цифры и неоднозначные знаки
не определяют раскладку; используется последний однозначно преобразованный
символ. Если такого символа нет, раскладка остаётся прежней.

Качественный успех: одно намеренное действие даёт предсказуемый результат;
после конвертации можно продолжать ввод в целевой раскладке. Проверяемые
метрики: все acceptance cases проходят; ноль принудительных восстановлений
раскладки при смене фокуса; ноль переключений при неопределённом направлении;
ноль ложных сообщений об успешном выборе источника в negative cases.
Сбор телеметрии для этих метрик не требуется.

## Проверенные исходные факты

- `Sources/LangConvert/main.swift`, `KeyboardAutomation.switchLocale`:
  отправляет Control + Space, не читает активный источник и не подтверждает
  итоговый выбор. Это команда с системной семантикой, а не явный выбор пары.
- `LayoutConverter.convert` возвращает преобразованный текст; направление
  отдельных символов вычисляется, но целевой источник наружу не передаётся.
- `KeyboardLayoutProvider.preferredConversionSources` выбирает существующую
  рабочую пару. При более двух раскладках предпочитается первая пара разных
  языков, затем первые две. Фактический код точнее общего описания в README.
- EN/RU fallback существует; рабочий источник должен определяться по его
  идентичности, а не по языку интерфейса AppLanguage.
- `convertSelection` использует копирование/вставку и фиксированные задержки;
  отправленное событие вставки само по себе не подтверждает замену текста.
- Памяти раскладок отдельных окон и восстановления по смене приложения нет.
  Причина описанной пользователем самостоятельной смены на его Mac неизвестна.
- Текущий Python-тест проверяет копию преобразования символов, а не Swift
  интеграцию с фокусом, hotkeys и системными источниками.

## Область задачи и observable contract

### Ручное переключение

1. Пользователь вызывает существующую команду переключения.
2. LangConvert получает актуальный системный источник для текущего контекста.
3. Если источник входит в рабочую пару, выбирает второй источник этой пары.
4. Проверяет фактический результат и различает успех, отказ и отсутствие
   подтверждения. Нельзя выдавать отправленное событие за успех.
5. Не хранит собственную авторитетную раскладку для окна или приложения.
   Системные переключения, включая восстановление документа, принимаются.

### Конвертация

1. Пользователь выделяет текст и вызывает существующую команду конвертации.
2. Приложение сохраняет контекст операции и преобразует текст с существующими
   правилами, включая смешанный ввод и EN/RU fallback.
3. Определяет целевой источник по последнему однозначно преобразованному
   символу, а не большинству букв и не текущей раскладке. Для конца строки
   с пробелами/цифрами/неоднозначными знаками поиск идёт назад.
4. После подтверждённой замены выделения явно выбирает этот источник.
5. Если источник уже активен, не выполняет лишний переход.
6. При успешной замене, но неуспешной смене источника, сообщает частичный
   результат. Не откатывает уже заменённый текст вслепую.

### Определённое поведение на границах

- Сохраняется существующий выбор рабочей пары; новый UI выбора пары не входит
  в задачу. При более двух источниках обе операции используют одну и ту же пару.
- Если текущий источник вне пары, ручная команда не угадывает «противоположный»:
  источник остаётся прежним, пользователь получает понятную причину.
- Если пара неполна, источник недоступен, выключен или исчез в ходе операции,
  не выбирается произвольный запасной источник. Ошибка выбора различается
  от результата преобразования текста.
- Fallback преобразования текста сохраняется. Автоматический выбор после него
  допускается только при однозначной связи направления с доступным источником.
- При отсутствующем выделении, отказе разрешения, ошибке чтения или замены
  раскладка не меняется. При неподтверждаемой замене нельзя объявлять успех
  и выполнять новое переключение на основании одного таймера.
- Если во время операции сменился целевой контекст ввода, нельзя вставлять
  текст или применять отложенную смену источника к другому окну. Отменять
  оставшиеся действия; не красть фокус обратно. Уже завершённую замену
  не объявлять отменённой.
- Повторные команды не должны приводить к наложению вставок и отложенных
  переключений. Безопасно отклонить команду, пока предыдущая не завершена.
- Подтверждение результата ограничено по времени, не блокирует интерфейс
  бесконечными ожиданиями и не переигрывает последующее действие пользователя.

Это консервативные уточнения технических вопросов Brief для рассматриваемой
Task: вне поддерживаемого сценария не угадывать и не менять чужой контекст.
Они предъявляются пользователю вместе со всей Task для утверждения.

| AC14 | Fallback и варианты EN/RU | Преобразование сохранено; направление связано с конкретным доступным источником |

| AC18 | EN/RU и доступная пара других языков | Базовое преобразование сохраняется; неопределённое направление не угадывается |

## Риски, зависимости и исключения

- Системная память раскладки документа остаётся под управлением macOS.
- Замена в сторонних редакторах зависит от разрешений и доступности информации
  о фокусе/тексте. Неподдерживаемые случаи должны завершаться без ложного успеха.
- Источник ввода не всегда соответствует простому языку или таблице символов;
  нельзя приравнивать все методы ввода к EN/RU или выбирать по имени UI.
- Соседние функции: конвертация, горячая клавиша переключения, обратная связь
  и временный буфер обмена. Существующее поведение текста не должно регрессировать.
- Исправление modifier-only hotkeys, новый индикатор, память раскладок окон,
  изменение системных настроек, новый редактор и телеметрия вне scope.
- Прямое подавление всех системных смен раскладки отвергнуто: требуется принимать
  фактическое состояние, а не бороться с системным восстановлением.
- Сохранение слепой имитации Control + Space отвергнуто: не обеспечивает
  переключение относительно текущего источника рабочей пары.
- build/LangConvert.pkg не обновлять вручную в Linux. При отдельно разрешённой
  публикации сборка дистрибутива выполняется существующим macOS Actions workflow.
- Push, merge, deployment и изменение CI не включены автоматически.
